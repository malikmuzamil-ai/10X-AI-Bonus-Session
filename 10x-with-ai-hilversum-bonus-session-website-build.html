01

Create the project folder

5 min
  1. On the desktop, create one new folder named for both their business and their personal brand, e.g. summit-ridge-malik-website. This keeps the folder identifiable if they're managing more than one project later.
  2. Drop every foundation document from Step 00 straight into this folder, all five files, no sub-folders needed.
  3. Add their logo file and any existing photos into the same folder, or a media sub-folder if they'd rather keep it tidy. Either works, Claude will find both.
Confirm before moving on Every participant's folder should contain the five foundation docs plus whatever images they have, before anyone opens Claude Code. This is the one step worth a visible round of confirmation in chat.
02

Open the folder in Claude Code

3 min
  1. Open Claude Desktop → click the Code tab (next to Chat and Cowork) → New Session.
  2. Click Open Folder, select the folder built in Step 01, and click Trust Workspace when prompted.

Everyone's folder tab at the top should now show their business + personal brand folder name. Don't advance until every screen shows this.

03

Install the two design skills

12 minOne-time onlyVerified against Anthropic docs

These two skills are the difference between a site that looks like everyone else's AI output and one that doesn't, say this out loud, it's why the room shouldn't skip it. Installed once, both are available automatically in every future project, no reinstalling per session.

The exact click path below is the confirmed one from Anthropic's own plugin documentation, not a guess, so it should match what's on screen exactly. Walk through it slowly the first time; it moves fast on the second skill.

Part A: Add the marketplace (once, then reused for both skills)
Left sidebar→ Customize→ Plugins tab→ "+" button→ Add marketplace
  1. Click Customize in the left sidebar. This is the single home for plugins, skills, and connectors, everything for this step lives here.
  2. Open the Plugins tab.
  3. In the Personal plugins section, click the "+" button.
  4. Select Add marketplace.
  5. Choose Add from a repository, this is the option that accepts a GitHub URL directly, rather than picking from Anthropic's pre-built list.
Part B: Sync Skill 1, Frontend Design (Anthropic)

Expands font and layout choices beyond generic defaults. Paste this repo URL into the field from the step above:

https://github.com/anthropics/skills/tree/main/skills/frontend-design
  1. Paste the URL and let it sync, this registers the marketplace but doesn't install anything yet.
  2. Back in the Plugins tab, click Browse plugins to see what the marketplace makes available.
  3. Find Frontend Design in the list and click Install.
Part C: Sync Skill 2, UI/UX Pro Max

A library of color palettes, font pairings, and layout patterns to pull from. Same five-click path from Part A, new URL:

https://github.com/nextlevelbuilder/ui-ux-pro-max-skill
  1. Repeat Part A's path: "+" → Add marketplace → Add from a repository.
  2. Paste this second URL and let it sync.
  3. Browse plugins, find UI/UX Pro Max, click Install.
Part D: Confirm both are live

Type / in the chat box, or click the "+" next to the message field. Both skills should appear in the list that pops up. That's the real confirmation, not the install button itself, an install can silently fail to register.

Confirm before Step 5 Have everyone type / and read out loud what shows up. A missed install is invisible until the finished site looks generic, and by then it's a rebuild, not a quick fix. Don't move the room forward until every screen shows both skills.

05

The build prompt, and the follow-ups

25–35 min

This is the step that pulls everything together, reference screenshot, logo and photos, both installed skills, and all five foundation documents. Read it aloud line by line; participants adapt the specifics as they type. It's meant to be extensive, a short prompt is exactly how generic sites happen. One long, specific prompt beats five short vague ones, because Claude only gets the full picture once, right at the start.

Setup, before typing anything
  1. Paste the reference screenshot from Step 04 into the Code chat.
  2. Type / and select Frontend Design, so the layout and typography guidance is active.
  3. Type / again and select UI/UX Pro Max, so the palette and pattern library is active alongside it.
  4. With both skills selected, type or voice-to-text the prompt below, filling in the highlighted fields.
Prompt 1: The initial build
Please build me a complete business website for [BUSINESS NAME], based here in [CITY, STATE]. Use the Frontend Design skill and the UI/UX Pro Max skill together for this build, layout, typography, and color decisions should come from those skills, not from generic defaults. Use the reference image I've shared as layout and feel inspiration, but build it entirely around my own brand, my logo, my brand colors, and the photos already in this folder. I've included my full foundation in this project folder. Read all five documents before writing a single line of copy: - Business Plan - ICP document - Messaging House - Brand Positioning - Business Inbox Pull my actual positioning, my real offer, and my ICP's language directly from those documents, don't invent generic copy or paraphrase them into something vaguer. Every headline, subhead, and call-to-action should trace back to a specific line in one of those five documents. The site should read like it was written by someone who has actually read my business plan, not like a template with my name dropped in. Sections I want included: [list anything specific, before/after work, a process breakdown, testimonials, service list] Build this as a single HTML file so it's simple to deploy. Before you write anything, tell me which specific lines from my foundation documents you're planning to use for the headline and the About section, so I can confirm before you build the rest. Please ask me any other questions you need before you start.

If Claude comes back with questions before it builds, have participants answer straight from the Messaging House and Business Inbox documents rather than typing anything new from memory.

Before submitting Set the mode to Auto at the bottom of the chat so the build runs through without stopping for permission on every file. Walk the room to confirm everyone has this toggled first.

Let it run, a first full draft typically takes 5–10 minutes.

Prompt 2: Strip the AI glow

Run this immediately after the first draft, before anyone reacts to the design. First-pass copy from any model tends to carry a generic sheen, safe adjectives, rounded-off claims, sentences that could belong to any business in the category. This prompt sends it back through with the actual source material.

Read through every section of copy on this site and flag anything that sounds like generic AI-written text, vague claims, safe adjectives, sentences that could apply to any business in this industry, phrasing that doesn't sound like a real person talking about their own business. For each flagged section, rewrite it using the actual language from my Messaging House and Business Positioning documents. If a claim in the copy isn't directly supported by something in my Business Plan or Business Inbox, either cut it or replace it with something that is. Keep sentences short and specific. Say what the business actually does, for the actual clients described in my ICP document, using their language, not marketing-speak.
Prompt 3: A second design pass

Naming both skills again here matters, Claude sometimes leans on one and forgets the other by the third or fourth prompt in a session.

Using the Frontend Design skill, take one more pass on the layout, spacing, and typography, look specifically for anything that reads as a default AI-generated template rather than a deliberate choice for this business. Using the UI/UX Pro Max skill, check the current color and font pairing against the library, if there's a stronger, more specific pairing for a [BUSINESS INDUSTRY] business, apply it. Keep my logo and existing photos as the anchor, don't replace them, just make sure everything around them now looks intentional rather than templated.
Prompt 4: Foundation cross-check

The closing accuracy pass, run this once the design and copy both feel right, right before Step 06.

Go through the site one more time, section by section, and check every claim, offer, and detail against my five foundation documents, Business Plan, ICP, Messaging House, Brand Positioning, and Business Inbox. Flag anything on the site that doesn't match what's actually in those documents, and tell me what you found before changing anything.
06

First look, live preview

5 min
  1. Click Preview in the top-right corner once the build finishes.
  2. Have everyone scroll their own site top to bottom once, out loud on the call, one thing they like, one thing they'd change.

This surfaces the common fixes before individual editing time, and normalizes a rough first draft instead of letting people read it as a personal miss.

07

Guided refinement round

20–30 min

Give the room a short, specific punch list rather than open-ended "fix whatever you want" time, open-ended time is where non-technical participants freeze.

  • Fix the hero fold: "The hero section is getting cut off, make sure all elements fit above the fold."
  • Simplify a busy section: use the Select tool (top-right of preview), click the section, and type a plain fix, "simplify this to one full-width image instead of three cropped ones."
  • Mark up visually: use the pencil/draw tool to circle the exact spot that's wrong, add a note, and send. Fastest fix path for anyone who struggles to describe a layout problem in words.
  • Cross-check against the Messaging House: is the headline actually the core message they defined on Day 1, or did Claude paraphrase it into something generic? Worth one direct pass.

Before moving on, confirm every real business detail is correct: phone number, service list, hours, contact method. Easy to leave as placeholder text if nobody checks.

Facilitator should float and unstick anyone whose prompt isn't landing, rather than letting them keep retrying the same phrasing alone.

08

Deploy live on Netlify

15–20 minNo domain purchase required

No hosting plan to buy, no checkout flow. This gets a real, shareable HTTPS link in minutes, on a free subdomain. A custom domain can be connected later if someone wants one.

Netlify Drop
  1. Go to app.netlify.com/drop in a browser.
  2. Drag the entire project folder straight into the browser window.
  3. Netlify deploys instantly and returns a live URL, something like https://random-name-123.netlify.app.
  4. Optional: create a free Netlify account to keep the site permanently and rename the subdomain under Site Settings → Change Site Name.
  5. Optional: connect a custom domain later under Domain Settings, if they buy one through Netlify or point one they already own.

This is the path to run live in the room, zero setup, no sign-in required to get the first URL.

Close the loop Have everyone drop their live URL into the group chat once it's up. That's the session's finish line, and a quick roll call of who made it all the way through.

Comprehensive Facilitator Notes

Running the room

The five foundation documents are the content source, not background reading

Everything in Step 05's prompt depends on Claude actually reading the Business Plan, ICP, Messaging House, Brand Positioning, and Business Inbox, not on the facilitator summarizing them. If a participant only has two or three of the five, flag it before Step 05; a partial foundation produces a partial, more generic result.

Verify both skills before Step 05, for everyone

A missed marketplace install is invisible until the finished site looks templated, and by then it's a rebuild rather than a quick fix. Do a visible check-in right after Step 03, have each participant type / and read out loud what shows up, rather than trusting the install button alone.

The four prompts in Step 05 do different jobs, don't collapse them

Prompt 1 builds the site from the foundation documents. Prompt 2 strips out the generic AI tone that first drafts tend to carry, even when the underlying facts are right. Prompt 3 goes back to the two skills by name for a second design pass, since Claude will sometimes lean on one skill and quietly drop the other by the third or fourth exchange. Prompt 4 is the accuracy audit against all five documents. Running them in order, rather than folding the fixes into one long ad-hoc request, is what keeps the output specific instead of averaging back toward generic.

Keep the asset bar low

The strongest sessions run on a logo and whatever photos already exist, nothing produced specifically for this. If someone has no assets at all, let Claude propose a palette and placeholder treatment in Step 05 rather than sending them off to source images mid-session.

Normalize the rough first draft

Step 06's "one like, one change" round matters more than it looks. Non-technical participants often read a rough first pass as a personal failure rather than the normal starting point. Hearing peers hit the same rough edges keeps the room's energy up going into refinement.

Open-ended editing time stalls the room

Give the punch list in Step 07 rather than "fix whatever you want." Participants who don't know what to ask for tend to freeze, then quietly disengage. A facilitator walking the room to unstick specific prompts keeps momentum better than open group Q&A.

Netlify Drop is the whole deployment step

It needs no account, no terminal, and no domain purchase, just drag the folder in and get a URL back. This is what keeps the last part of the session fast for a fully non-technical room.

Close on the shared URL, not on hosting logistics

The free subdomain is the finish line for this session, a custom domain is a follow-up task, not a requirement to leave with something real and live. Having everyone post their URL in the group chat gives a visible finish and a quick roll call of who made it through deploy.
